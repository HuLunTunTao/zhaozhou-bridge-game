# 第一章第二关《弧拱定式》· 实现设计

> 本文件为**代码实现稿**。与 `artbook/第二关数值.txt` 的 Godot 取向版总稿并列，不覆盖总稿；两者差异集中在本文第 10 节"偏差说明"。

## 1. 本关核心体验

- 承接第一关「踏勘洨河」的成长，李春进入"桥法确定者"阶段。
- 战场围绕**中央绘样台**：玩家需先派测量工完成 3 处参数采样，再把李春送上绘样台执墨定拱；完成后进入"猎杀阶段"——累计击退 8 名受驱役之敌即胜利。
- 唯一 Boss **旧制监工**固守绘样台后方，**完全免疫伤害、不移动、不攻击**，只做召唤与督令施压。
- 玩家始终在取参、控中、清怪之间做权衡。

## 5. Boss 行为规则（旧制监工）

每当 `team_turn_started(ENEMY_TEAM)` 触发（敌方回合开始）时，level 脚本按顺序执行：

1. **群体督令**：所有存活小怪获得 `rule_group_boost` 状态，本回合造成伤害 **+10%**，持续 1 回合。
2. **单体督令**：选出 HP 最高的一只小怪获得 `rule_single_boost` 状态，本回合造成伤害 **+30%**，持续 1 回合。
3. **召唤**：若场上小怪数 < 5，按固定轮换召唤 1 只；若本回合有 "小怪占台奖励"，召唤数 +N。

### 召唤轮换（固定序列）

```text
循旧匠首 → 高拱幻影 → 循旧匠首 → 循旧匠首 → 重墩石像 → (循环)
```

### 小怪占台 → 下回合 +1

- 每当**玩家回合开始**（即敌方回合结束）时，扫描所有存活小怪：若位于绘样台 4 格内且本实例尚未触发过，则记录 instance_id 并累加 `_pending_summon_bonus += 1`。
- `_pending_summon_bonus` 在下个 Boss 回合被消费并归零。
- 同一只小怪**终生只触发一次**。

### 免疫实现

- `UnitData.old_method_supervisor.tres`：`move_limit=0`、`skill_limit=0`、`ap_max=0`、`skills=[]`，AI 无法为 Boss 生成任何动作。
- 受伤瞬间 `unit_hp_changed(boss, old, new)` 触发 `_on_stage_hp_changed` 将 `current_hp` 回滚到 `old_hp`，等价于"任意伤害都无效"。
- Boss 永远不会触发 `unit_died`，因此不会被当作"被击退小怪"计入 `_minion_kills`。

## 6. 关卡状态机（四段式）

沿用 1-1 的 `TaskState` 模式：

```gdscript
enum TaskState { TASK1_PARAMETERS, TASK2_PLATFORM, TASK3_ARCH, TASK4_HUNT }
```

| 任务 | 目标 | 推进条件 |
|---|---|---|
| TASK1 | 完成 3 个参数点 | 三个 `ParameterPointTile.completed == true` |
| TASK2 | 李春抵达中央绘样台 | `unit_move_completed(Li Chun)` 且 `cell in DRAFTING_CELLS` |
| TASK3 | 李春执行「执墨定拱」 | `lc_ink_set_arch` 技能合法释放 |
| TASK4 | 击退 8 名受驱役之敌 | `_minion_kills >= 8` 触发 `check_victory()` |

参数点推进期间即可自由攻击、击退小怪，`_minion_kills` 一直累计，不在 TASK4 才开始清零。

## 7. 胜负条件

### 胜利

1. 当前任务进入 TASK4；
2. `_minion_kills >= 8`；
3. `check_victory()` 返回 true → 触发成长面板。

### 失败（保留）

- 李春倒下。
- `round_number > 12`。

开局 `Notify`：*「派测量工到 3 个参数点施放「测尺取参」。」*

## 9. 战斗引擎微调

为实现督令增益，`scripts/combat/combat_resolver.gd` 在攻击方状态修正步骤里新增两个分支：

```gdscript
"rule_single_boost":
    multiplier *= 1.30
"rule_group_boost":
    multiplier *= 1.10
```

督令 `remaining_turns = 1`，小怪自身回合结束时 `_tick_statuses` 会扣至 0 并清除。无 `trigger_once`，即"本回合所有攻击都享增益"。

`scripts/combat/skill_executor.gd` 中为 `take_parameter / confirm_parameter / ink_set_arch` 三个 `extra_effect_id` 添加了空处理分支，仅写日志；真正的交互判定全部走关卡的 `_on_skill_executed` override。
