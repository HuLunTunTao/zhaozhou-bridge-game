# 07 -- 测试与调试

> 本章介绍如何在 Godot 编辑器中测试关卡、查看运行时信息、排查常见问题。

---

## 7.1 运行关卡

### 方法一：直接运行当前关卡场景（推荐开发时使用）

1. 确保你的关卡 `.tscn` 文件当前正在编辑器中打开
2. 按 **F6**（或顶部工具栏中的"运行当前场景"按钮）
3. 游戏窗口会直接加载当前关卡，跳过主菜单

> 提示: F6 运行是最快的测试方式，每次修改后按 `Ctrl+S` 保存，然后 F6 运行即可看到效果。

### 方法二：从主菜单进入关卡

1. 按 **F5** 运行整个项目（从主菜单开始）
2. 在主菜单中点击 **开始**
3. 在关卡选择界面中点击对应关卡按钮

> 注意: 如果你的关卡没有在选关界面中出现，说明还没有在 `scripts/game_state.gd` 中注册。参见 [08-关卡集成](08-integration.md)。

### 方法三：使用调试关卡

项目中有一个 `scenes/debug/debug_battle.tscn`，它会程序化生成一个 10x10 的平坦地图。这个场景适合用来：

- 测试单位移动是否正常
- 验证 UI 是否正确显示
- 调试新功能

## 7.2 游戏内操作

运行关卡后，以下是玩家的基本操作：

| 操作 | 输入方式 | 说明 |
|------|----------|------|
| 选择己方单位 | 右键点击单位 | 选中后自动显示移动范围（黄色菱形）+ 状态栏技能按钮 |
| 移动单位 | 右键点击高亮格子 | 单位沿路径移动到目标格，扣除 AP |
| 使用技能 | 点击状态栏技能按钮 -> 右键点击释放点 | 蓝色=释放范围，红/绿/黄色=影响区域 |
| 切换到移动 | 点击状态栏"移动"按钮 | 使用技能后若还有 AP，可切换回移动模式 |
| 取消操作 | 左键 / ESC | 取消当前选中或技能瞄准 |
| 查看任意单位信息 | 右键点击任意单位 | 底部状态栏显示该单位完整信息 |
| 查看路径消耗 | 悬停鼠标到目标格 | 路径终点显示 AP 消耗和剩余 |
| 结束回合 | 点击右下角"结束回合"按钮 | 手动结束当前队伍回合 |
| 移动镜头 | 方向键 / 右键拖拽 / 鼠标边缘 | 三种方式可混合使用 |
| 缩放镜头 | 鼠标滚轮 | 向上放大（最大2x），向下缩小（最小0.5x） |
| 打开设置 | 点击右上角齿轮按钮 | 打开设置面板（可返回主菜单） |

### 技能目标颜色说明

使用技能时，预览区域的颜色按技能类型区分：

| 区域 | 颜色 | 说明 |
|------|------|------|
| 释放点范围 | 蓝色半透明 | 所有可选的释放点（cast_offsets） |
| 攻击影响区域 | 红色半透明 | ATTACK 类型技能的伤害区域 |
| 辅助影响区域 | 绿色半透明 | ASSIST 类型技能的增益区域 |
| 交互影响区域 | 黄色半透明 | INTERACT / ASSIST_INTERACT 类型技能的区域 |

### 回合流程

1. 当前队伍的回合开始，顶部标签显示 `[ 队伍名 的回合 ]`
2. 如果是玩家队伍：
   - 右下角出现"结束回合"按钮
   - 选择单位并执行移动/技能
   - 单位的 AP 用尽后自动标记为"已行动"
   - 单位还有 AP 时可以继续移动或使用技能（不限顺序）
   - 所有单位行动完毕后可手动点击"结束回合"
3. 如果是 AI 队伍：
   - AI 自动操控每个单位（当前为随机移动一步）
   - 所有 AI 单位行动完毕后自动进入下一队伍

### AP 与行动机制

每个单位在回合开始时 AP 恢复至满（`ap_max`）。一个回合内可以：

- **多次移动**：每次移动扣除路径上每格的 AP 消耗（`move_cost_per_tile` + 地形额外消耗）
- **使用技能**：每次使用扣除技能的 `ap_cost`
- **混合行动**：先移动 -> 使用技能 -> 再移动（只要 AP 足够）

> 提示: `move_limit` 和 `skill_limit` 限制的是次数而非 AP。例如工匠 `move_limit = 1` 意味着每回合只能移动 1 次，即使还有剩余 AP。

## 7.3 运行时信息查看

### 底部状态栏

运行时，底部状态栏显示选中单位的详细信息：

**活跃单位（当前队伍的可操作单位）显示：**

```
[头像] 李春 | HP:130/130 | AP:100/100 | 当前属性:无 固有属性:无 | [移动] [技能1] [技能2] ...
```

- 左侧：头像（来自 UnitData.portrait）
- 中间：名称、HP 进度条、AP 进度条、当前属性/层数、固有属性/层数
- 右侧：1 个移动按钮 + 最多 5 个技能按钮（灰色=不可用/AP不足）

**非主角己方单位额外显示：**

```
移动:0/1 技能:0/1
```

（显示当前回合已用次数/限制次数）

**非活跃单位（查看信息）：** 显示同样的属性信息，但技能按钮不可点击。

**状态栏背景色按阵营变化：**

| 阵营 | 背景色 | 条件 |
|------|--------|------|
| 主角（李春） | 深蓝色 | `is_hero = true` |
| 己方 | 深绿色 | `camp = ALLY` |
| 敌方 | 深红色 | `camp = ENEMY` |
| 默认 | 深灰色 | 无 combat_stats 时 |

### 属性显示

状态栏显示两组属性信息：

- **当前属性（Cur）**：单位当前身上的五行属性和层数。技能命中后会变化。
- **固有属性（Inn）**：单位天生的属性。每回合开始时回补。

属性用符号+颜色区分：

| 属性 | 符号 | 颜色 |
|------|------|------|
| 无 | 无 | 灰色 |
| 金 | ◇金 | 金黄 |
| 木 | ✿木 | 绿色 |
| 水 | ≈水 | 蓝色 |
| 火 | ✦火 | 橙红 |
| 土 | ▦土 | 棕色 |

### 战斗日志

所有战斗操作都会在 Godot 编辑器的 **输出 (Output)** 面板中打印详细日志，格式为 `[战斗] ...`。日志包括：

- 回合开始/结束
- 单位移动（起点、终点、AP消耗、AP剩余）
- 技能释放（施放者、技能名、目标格、目标单位）
- 伤害计算过程（基础伤害、化势倍率、附加伤害、最终伤害）
- 属性变化（附着前后的属性和层数）
- 状态施加（状态名、持续回合）
- DoT 伤害（回合结束时的持续伤害）
- 击杀事件

示例日志：

```
[战斗] ═══ 玩家队伍 的回合开始 ═══
[战斗] 回合开始: [玩家队伍] 李春 HP:130 AP:100
[战斗] 李春 移动 (5, 3) → (7, 3) (消耗16AP 剩余84AP)
[战斗] 李春 在(7, 3) 释放【投石遏流】→ 目标格(8, 3)
[战斗]   目标: 暗涌 在(8, 3) (HP:68/68 属性:水×2)
[战斗]   伤害计算: 李春 → 暗涌
[战斗]     基础: 24 × 0.95 = 22.8
[战斗]     化势: 遏流 倍率×1.00
[战斗]     附加伤害: +10
[战斗]     最终伤害: 33
[战斗]   属性变化: 暗涌 水×2 → 土×2
[战斗]   状态施加: 暗涌 获得【silt_lock】3回合
```

> 提示: 这些日志对排查"为什么伤害不对"或"为什么化势没触发"非常有用。重点关注"化势"行的倍率和"附加伤害"值。

### 头顶状态条

每个单位头顶会显示 HP 条和 AP 条（上下排列，各自独立 1px 描边）：

**HP 条**（上方，4px 高）：
- 亮绿 (0.15, 0.95, 0.15) = HP > 60%
- 亮黄 (1.0, 0.9, 0.1) = HP 30%~60%
- 亮红 (1.0, 0.15, 0.15) = HP < 30%

**AP 条**（HP 下方 1px 间距，3px 高）：
- 亮蓝 (0.25, 0.55, 1.0) = AP > 60%
- 淡蓝 (0.5, 0.55, 0.8) = AP 30%~60%
- 暗灰 (0.35, 0.3, 0.35) = AP < 30%

**可见性规则**：始终显示。

#### 布局参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 条宽度 | 30px | HP/AP 条共用 |
| HP 条高度 | 4px | — |
| AP 条高度 | 3px | — |
| Y 偏移 | -24px | HP 条顶端距精灵原点 |
| 间距 | 1px | HP 条与 AP 条之间 |
| 描边 | 1px | 黑色外框，包裹整体 |

#### 渲染层级（z_index）

| 层级 | z_index | z_as_relative | 说明 |
|------|---------|---------------|------|
| 头顶 HP/AP 条 | 100 | false（绝对） | 始终在最上层，不被其他单位遮挡 |
| 伤害弹字 | 90 | true（默认） | 在 sprite 之上，状态条之下 |
| 角色 sprite | 0 | true（默认） | 正常游戏世界渲染 |
| TileMap 图层 | -2 ~ 2 | — | 地形层级 |

### 化势提示

当技能触发五行化势（相克或相生反应）时，屏幕会有三处联动反馈：

**1. 屏幕中心闪现化势名**（约 0.8 秒淡出）：

```
制势 · 遏流
```

**2. 被攻击单位头顶浮现元素对比**（彩色 + 上浮淡出）：

```
土×2 → 水×2
```
（土为棕黄色，水为天蓝色）

左侧为技能附着的元素×数量，右侧为目标攻击前的附着元素×数量。

**3. 右上角 Notify 通知**（富文本 BBCode，4 秒后淡出）：

```
【制势·遏流】
土×2 → 水×2
伤害倍率 ×1.00
附加伤害 10
施加【壅水】3回合
```

字段说明（按 `PhaseData` 存在性拼接）：
- 首行：`【{category}·{phase_name}】`（category 为"制势"或"承势"）
- 第二行：攻击元素 → 目标元素（彩色 BBCode）
- 伤害倍率（仅在 ≠1.0 时显示）
- 附加伤害（仅在 >0 时显示）
- 施加状态（仅在 `apply_status_id` 非空时显示）

### 元素颜色表

所有元素颜色由全局类 `ElementColors` (`scripts/data/element_colors.gd`) 统一管理，供状态栏、头顶 popup、右上角通知共用。

| 元素 | 颜色 | RGB |
|------|------|------|
| 金 | 金黄 | (255, 215, 70) |
| 木 | 草绿 | (110, 220, 110) |
| 水 | 天蓝 | (90, 180, 255) |
| 火 | 红 | (230, 70, 60) |
| 土 | 棕黄 | (200, 150, 80) |
| 无 | 灰 | (140, 147, 161) |

如需调整颜色，修改 `ElementColors.COLORS` 字典即可，所有 UI 自动同步。

## 7.4 常见问题排查

### 问题 1：运行后看不到地图

**可能原因：**
- `TileMaps` 下没有 TileMapLayer
- TileMapLayer 没有设置 TileSet
- TileMapLayer 上没有绘制任何地块

**排查步骤：**
1. 检查场景树中 `TileMaps` 下是否有 TileMapLayer 子节点
2. 选中 TileMapLayer，检查检查器中的 **Tile Set** 是否有值
3. 在 2D 视图中，该层上是否有绘制的地块

---

### 问题 2：角色不显示 / 显示在错误位置

**可能原因：**
- 单位节点不在 `Entities/Units/` 下
- 单位放置位置离地图太远
- `obstacles_tilemap_layer` 未设置

**排查步骤：**
1. 检查单位节点是否在 `Entities/Units/` 路径下
2. 在 2D 视图中，单位是否在地图范围内
3. 检查根节点的 `Obstacles Tilemap Layer` 属性是否已设置

---

### 问题 3：角色无法移动

**可能原因：**
- `MovementManager` 的 `Movement Tilemaps` 未配置
- 地表层没有使用 Terrain 模式绘制
- 所有格子被障碍物覆盖
- 单位的 `move_limit` 已用完

**排查步骤：**
1. 选中 `MovementManager` 节点，检查 **Movement Tilemaps** 是否包含地表层
2. 确认地表层使用了 Terrain 模式绘制（参见 [02-地形绘制](02-terrain-painting.md)）
3. 检查 **Obstacle Tilemaps** 中的障碍物层是否覆盖了你想让角色走的区域
4. 查看战斗日志中 AP 和移动次数的信息

---

### 问题 4：点击角色无反应

**可能原因：**
- 不是当前队伍的回合
- 角色已经行动过了（AP耗尽或手动结束）
- 角色正在移动中
- 过场动画或对话框正在播放

**排查步骤：**
1. 查看顶部标签，确认当前是哪支队伍的回合
2. 确认点击的角色属于当前队伍
3. 确认不在过场动画或对话框中

---

### 问题 5：运行时报错 "Node not found"

**原因：** 关卡脚本中的节点路径与场景树不匹配。

**输出面板中的典型错误信息：**
```
Node not found: "Entities/Units/PlayerB" (relative to "/root/Level1-5")
```

**解决：** 对照场景树中的节点名称，修正脚本中的 `$"..."` 路径。

---

### 问题 6：运行时报错 "obstacles_tilemap_layer is not set"

**原因：** 根节点的 `obstacles_tilemap_layer` 属性未设置。

**解决：**
1. 选中关卡根节点
2. 在检查器中将 **Obstacles Tilemap Layer** 指定为障碍物层
3. 参见 [01-地图创建](01-map-creation.md) 第 2.5 节

---

### 问题 7：移动范围显示不正确（太大或太小）

**可能原因：**
- 地形 Terrain 未正确设置
- 单位的 `move_cost_per_tile` 或 `ap_max` 值异常
- `MovementManager` 的层配置有误
- 单位有移动增/减状态（迟滞、陷裂等）

**排查步骤：**
1. 选中单位节点，展开 UnitData，检查 `ap_max` 和 `move_cost_per_tile` 的值
2. 检查地表层的 Terrain 是否正确（参见 [02-地形绘制](02-terrain-painting.md)）
3. 确认 MovementManager 的 `Movement Tilemaps` 指向正确的地表层
4. 查看战斗日志中是否有状态修正信息

---

### 问题 8：镜头不动 / 镜头位置错误

**可能原因：**
- TileMaps 下没有有效地块
- TileMapLayer 的远处有遗留地块导致边界过大

**排查步骤：**
1. 检查每个 TileMapLayer 是否有误放的孤立地块
2. 尝试缩小镜头（滚轮向下）查看完整地图

---

### 问题 9：技能释放后没有效果

**可能原因：**
- AP 不足无法释放技能
- 释放点没有对方阵营的单位（攻击技能）
- 释放点没有友方单位（辅助技能）
- 技能的 `damage_ratio = 0` 且 `attach_amount = 0`

**排查步骤：**
1. 查看战斗日志中是否有"技能执行失败"的提示
2. 确认目标单位在技能的 `effect_offsets` 范围内
3. 确认阵营关系正确（攻击不能打同阵营，辅助不能加不同阵营）

---

### 问题 10：状态栏不显示技能按钮

**可能原因：**
- 选中的不是活跃单位（不是当前回合的队伍）
- 单位的 UnitData 中没有装配技能（skills 数组为空）
- 单位的 UnitData 未设置

**排查步骤：**
1. 确认选中的单位属于当前正在行动的队伍
2. 检查 UnitData 的 skills 数组是否有内容
3. 如果是运行时装配技能，检查 `_on_level_ready()` 中的代码

## 7.5 调试技巧

### 使用 print() 输出

在关卡脚本中添加 `print()` 语句来观察运行状态：

```gdscript
func _on_level_ready() -> void:
    print("关卡初始化完成")
    print("队伍数量: ", teams.size())
    for i in range(teams.size()):
        print("  队伍 %d: %s, %d 个单位" % [i, teams[i].team_name, teams[i].units.size()])
```

### 使用 Godot 远程场景树

运行游戏后，Godot 编辑器左上角的场景树面板会出现一个 **远程 (Remote)** 选项卡。切换到 Remote 可以查看运行时的实际节点树，确认：

- 单位是否被正确重新挂载到障碍物层
- 各节点的运行时属性值

### 查看战斗数据

在运行时，可以通过远程场景树选中 Unit 节点，查看其 `combat_stats` 属性来确认：

- 当前 HP、AP
- 当前属性和层数
- 已施加的状态列表
- 移动/技能使用计数

### 单独测试地图

如果你只想测试地图绘制（不需要角色和逻辑），可以：

1. 打开地图场景文件（`scenes/levels/maps/` 下的纯地图文件）
2. 按 F6 运行
3. 查看地图显示效果

## 7.6 性能注意事项

对于关卡设计师需要注意的性能相关事项：

- **地图大小**：不建议单层超过 50x50 格。过大的地图会导致 Dijkstra 路径搜索变慢
- **TileMapLayer 层数**：建议不超过 5-6 层。每多一层都会增加渲染开销
- **单位数量**：建议单关卡不超过 15 个单位。过多单位会导致 AI 回合等待时间过长
- **过场图片**：图片分辨率建议与视口分辨率一致（960x540）或窗口分辨率（1920x1080）
