# 07 -- 测试与调试

> 本章介绍如何在 Godot 编辑器中测试关卡、查看运行时信息、排查常见问题。

---

## 7.1 运行关卡

### 方法一：直接运行当前关卡场景（推荐开发时使用）

1. 确保你的关卡 `.tscn` 文件当前正在编辑器中打开
2. 按 **F6**（或顶部工具栏中的"运行当前场景"按钮）
3. 游戏窗口会直接加载当前关卡，跳过主菜单

> 提示: F6 运行是最快的测试方式，每次修改后按 `Ctrl+S` 保存，然后 F6 运行即可看到效果。

### 方法二：从主菜单进入关卡

1. 按 **F5** 运行整个项目（从主菜单开始）
2. 在主菜单中点击 **开始**
3. 在关卡选择界面中点击对应关卡按钮

> 注意: 如果你的关卡没有在选关界面中出现，说明还没有在 `scripts/game_state.gd` 中注册。参见 [08-关卡集成](08-integration.md)。

### 方法三：使用调试关卡

项目中有一个 `scenes/debug/debug_battle.tscn`，它会程序化生成一个 10x10 的平坦地图。这个场景适合用来：

- 测试单位移动是否正常
- 验证 UI 是否正确显示
- 调试新功能

## 7.2 游戏内操作

运行关卡后，以下是玩家的基本操作：

| 操作 | 输入方式 | 说明 |
|------|----------|------|
| 选择己方单位 | 右键点击单位 | 选中后自动显示移动范围（黄色菱形）+ 状态栏技能按钮 |
| 移动单位 | 右键点击高亮格子 | 单位沿路径移动到目标格，扣除 AP |
| 使用技能 | 点击状态栏技能按钮 -> 右键点击释放点 | 蓝色=释放范围，红/绿/黄色=影响区域 |
| 切换到移动 | 点击状态栏"移动"按钮 | 使用技能后若还有 AP，可切换回移动模式 |
| 取消操作 | 左键 / ESC | 取消当前选中或技能瞄准 |
| 查看任意单位信息 | 右键点击任意单位 | 底部状态栏显示该单位完整信息 |
| 查看路径消耗 | 悬停鼠标到目标格 | 路径终点显示 AP 消耗和剩余 |
| 结束回合 | 点击右下角"结束回合"按钮 | 手动结束当前队伍回合 |
| 移动镜头 | 方向键 / 右键拖拽 / 鼠标边缘 | 三种方式可混合使用 |
| 缩放镜头 | 鼠标滚轮 | 向上放大（最大2x），向下缩小（最小0.5x） |
| 打开设置 | 点击右上角齿轮按钮 | 打开设置面板（可返回主菜单） |

### 技能目标颜色说明

使用技能时，预览区域的颜色按技能类型区分：

| 区域 | 颜色 | 说明 |
|------|------|------|
| 释放点范围 | 蓝色半透明 | 所有可选的释放点（cast_offsets） |
| 攻击影响区域 | 红色半透明 | ATTACK 类型技能的伤害区域 |
| 辅助影响区域 | 绿色半透明 | ASSIST 类型技能的增益区域 |
| 交互影响区域 | 黄色半透明 | INTERACT / ASSIST_INTERACT 类型技能的区域 |

### 回合流程

1. 当前队伍的回合开始，顶部标签显示 `[ 队伍名 的回合 ]`
2. 如果是玩家队伍：
   - 右下角出现"结束回合"按钮
   - 选择单位并执行移动/技能
   - 单位的 AP 用尽后自动标记为"已行动"
   - 单位还有 AP 时可以继续移动或使用技能（不限顺序）
   - 所有单位行动完毕后可手动点击"结束回合"
3. 如果是 AI 队伍：
   - AI 自动操控每个单位（当前为随机移动一步）
   - 所有 AI 单位行动完毕后自动进入下一队伍

### AP 与行动机制

每个单位在回合开始时 AP 恢复至满（`ap_max`）。一个回合内可以：

- **多次移动**：每次移动扣除路径上每格的 AP 消耗（`move_cost_per_tile` + 地形额外消耗）
- **使用技能**：每次使用扣除技能的 `ap_cost`
- **混合行动**：先移动 -> 使用技能 -> 再移动（只要 AP 足够）

> 提示: `move_limit` 和 `skill_limit` 限制的是次数而非 AP。例如工匠 `move_limit = 1` 意味着每回合只能移动 1 次，即使还有剩余 AP。

## 7.3 运行时信息查看

### 底部状态栏

运行时，底部状态栏显示选中单位的详细信息：

**活跃单位（当前队伍的可操作单位）显示：**

```
[头像] 李春 | HP:130/130 | AP:100/100 | 当前属性:无 固有属性:无 | [移动] [技能1] [技能2] ...
```

- 左侧：头像（来自 UnitData.portrait）
- 中间：名称、HP 进度条、AP 进度条、当前属性/层数、固有属性/层数
- 右侧：1 个移动按钮 + 最多 5 个技能按钮（灰色=不可用/AP不足）

**非主角己方单位额外显示：**

```
移动:0/1 技能:0/1
```

（显示当前回合已用次数/限制次数）

**非活跃单位（查看信息）：** 显示同样的属性信息，但技能按钮不可点击。

**状态栏背景色按阵营变化：**

| 阵营 | 背景色 | 条件 |
|------|--------|------|
| 主角（李春） | 深蓝色 | `is_hero = true` |
| 己方 | 深绿色 | `camp = ALLY` |
| 敌方 | 深红色 | `camp = ENEMY` |
| 默认 | 深灰色 | 无 combat_stats 时 |

### 属性显示

状态栏显示两组属性信息：

- **当前属性（Cur）**：单位当前身上的五行属性和层数。技能命中后会变化。
- **固有属性（Inn）**：单位天生的属性。每回合开始时回补。

属性用符号+颜色区分：

| 属性 | 符号 | 颜色 |
|------|------|------|
| 无 | 无 | 灰色 |
| 金 | ◇金 | 金黄 |
| 木 | ✿木 | 绿色 |
| 水 | ≈水 | 蓝色 |
| 火 | ✦火 | 橙红 |
| 土 | ▦土 | 棕色 |

### 战斗日志

所有战斗操作都会在 Godot 编辑器的 **输出 (Output)** 面板中打印详细日志，格式为 `[战斗] ...`。日志包括：

- 回合开始/结束
- 单位移动（起点、终点、AP消耗、AP剩余）
- 技能释放（施放者、技能名、目标格、目标单位）
- 伤害计算过程（基础伤害、化势倍率、附加伤害、最终伤害）
- 属性变化（附着前后的属性和层数）
- 状态施加（状态名、持续回合）
- DoT 伤害（回合结束时的持续伤害）
- 击杀事件

示例日志：

```
[战斗] ═══ 玩家队伍 的回合开始 ═══
[战斗] 回合开始: [玩家队伍] 李春 HP:130 AP:100
[战斗] 李春 移动 (5, 3) → (7, 3) (消耗16AP 剩余84AP)
[战斗] 李春 在(7, 3) 释放【投石遏流】→ 目标格(8, 3)
[战斗]   目标: 暗涌 在(8, 3) (HP:68/68 属性:水×2)
[战斗]   伤害计算: 李春 → 暗涌
[战斗]     基础: 24 × 0.95 = 22.8
[战斗]     化势: 遏流 倍率×1.00
[战斗]     附加伤害: +10
[战斗]     最终伤害: 33
[战斗]   属性变化: 暗涌 水×2 → 土×2
[战斗]   状态施加: 暗涌 获得【silt_lock】3回合
```

> 提示: 这些日志对排查"为什么伤害不对"或"为什么化势没触发"非常有用。重点关注"化势"行的倍率和"附加伤害"值。

### 头顶状态条

每个单位头顶会显示 HP 条和 AP 条（上下排列，各自独立 1px 描边）：

**HP 条**（上方，4px 高）：
- 亮绿 (0.15, 0.95, 0.15) = HP > 60%
- 亮黄 (1.0, 0.9, 0.1) = HP 30%~60%
- 亮红 (1.0, 0.15, 0.15) = HP < 30%

**AP 条**（HP 下方 1px 间距，3px 高）：
- 亮蓝 (0.25, 0.55, 1.0) = AP > 60%
- 淡蓝 (0.5, 0.55, 0.8) = AP 30%~60%
- 暗灰 (0.35, 0.3, 0.35) = AP < 30%

**可见性规则**：始终显示。

#### 布局参数

实现位于 `scenes/ui/combat/unit_hp_bar.gd`。

| 参数 | 值 | 说明 |
|------|-----|------|
| 条宽度 | 30px | HP/AP 条共用 |
| HP 条高度 | 4px | — |
| AP 条高度 | 3px | — |
| Y 偏移 | **-40px** | HP 条顶端相对 Unit 节点原点（Unit 原点在脚下，所以向上偏移 40px 才能到头顶） |
| 间距 | 1px | HP 条与 AP 条之间 |
| 描边 | 1px | 黑色外框，包裹整体 |

> 💡 提示: Y 偏移之所以是 -40 而不是更小的数字，是因为 Unit 原点约定在角色脚下（见 [03-单位配置 § 4.2 "第三步" 重要约定](03-unit-placement.md#重要约定unit-原点位于角色的脚下)）。从脚下往上 40 像素才到角色头顶。

#### 渲染层级（z_index）速查表

以下是项目中所有需要排序的元素的 z_index 值。**设计师添加新地形图层时请确认自己设定的 z_index 不超过 4**，否则会遮挡技能选点高亮。

| 层级 | z_index | z_as_relative | 代码位置 | 说明 |
|------|---------|---------------|---------|------|
| **AP 消耗标签** | **110** | false（绝对） | `scenes/levels/base_level/move_overlay.gd` | 移动时路径终点的 AP 消耗/余量文字，始终在最顶层 |
| 化势元素 popup | **106** | false（绝对） | `scenes/ui/combat/phase_element_popup.gd` | 头顶 `土×2 → 水×2` 文字 |
| 伤害弹字 | **105** | false（绝对） | `scenes/ui/combat/damage_popup.gd` | 浮动伤害/治疗数字 + 化势名 |
| 头顶 HP/AP 条 | **100** | false（绝对） | `scenes/ui/combat/unit_hp_bar.tscn` | 始终可见，不被 sprite 或地形遮挡 |
| **移动范围/技能选点 overlay** | **5** | true（默认） | `move_overlay.gd` / `skill_targeting.gd` | **必须 > 任何 TileMapLayer 的 z_index**，否则高亮会被障碍物层遮挡 |
| TileMap Obstacle 层 | 2 | true（默认） | 关卡场景中 `z=2` 命名的图层 | 障碍物图层 |
| TileMap 装饰层 | 1 | true（默认） | 关卡场景中 `z=1` 命名的图层 | 装饰图层 |
| 角色 sprite | 0 | true（默认） | Unit/Visual 子节点 | 正常游戏世界渲染 |
| TileMap 地表层 | 0 | true（默认） | 关卡场景中 `z=0` 命名的图层 | 地表图层 |
| TileMap 底层 | -1 ~ -2 | true（默认） | 关卡场景中 `z=-1` / `z=-2` 命名的图层 | 水面倒影、悬崖下方 |

> ⚠️ 注意: 如果你在关卡中新增一个 TileMapLayer 并把它的 Z Index 设置为 **5 或更高**，释放技能时蓝色/红色/绿色/黄色的选点高亮会**被这一层完全遮挡**。解决方法：把新图层的 Z Index 调低到 4 或以下，或者（如果确实需要更高）联系程序员调整 `scripts/combat/skill_targeting.gd` 的 `z_index`。

## 7.3b 化势反馈（三层 UI）

当技能触发五行化势（相克或相生反应）时，系统会**同时**在三个位置显示反馈。设计师**不需要配置任何东西**，战斗系统会自动处理。了解这三层反馈能帮助你理解玩家会看到什么，以及方便美术同事核对显示效果。

### 反馈一：屏幕中心闪现化势名

- **实现**: `scenes/ui/combat/phase_notification.gd`（`class_name PhaseNotification`）
- **样式**: 金黄色大字（font_size = 20），黑色描边，居中显示
- **时长**: 停留 0.8 秒 + 0.5 秒淡出
- **触发次数**: 每次技能施法最多触发一次（即使技能命中多个目标）
- **文本格式**: `{category} · {phase_name}`，例如 `制势 · 遏流` 或 `承势 · 淬锋`

```
          ┌────────────────────┐
          │                    │
          │   制势 · 遏流       │   ← PhaseNotification
          │                    │
          └────────────────────┘
```

### 反馈二：被攻击单位头顶的元素对比 popup

- **实现**: `scenes/ui/combat/phase_element_popup.gd`（`class_name PhaseElementPopup`）
- **样式**: HBoxContainer 三段布局，左右为彩色元素文字（用 `ElementColors.get_color` 着色），中间为白色箭头 `→`
- **动画**: 出现在目标头顶 y-38 像素处，1 秒内上浮 18 像素，0.6 秒后淡出（延时 0.6s 淡出 0.8s）
- **触发次数**: 每个被命中的目标各显示一次（命中多个时多次显示）
- **文本格式**: `{攻击元素名}×{附着量} → {目标元素名}×{目标原量}`

```
            ┌───────────────────┐
            │  土×2  →  水×2     │   ← PhaseElementPopup
            └─────────┬─────────┘
                      │
                ┌─────┴─────┐
                │   暗涌     │   ← 被击中的目标单位
                └───────────┘
```

左边"土×2"为棕黄色，右边"水×2"为天蓝色（颜色来自 `ElementColors`，见 [附录 B § B.13](appendix-creature-reference.md#b13-元素颜色全局类-elementcolors)）。

### 反馈三：右上角 Notify 详情通知

- **实现**: 复用全局 `Notify` autoload，`base_level.gd:746` 调用
- **位置**: `Notify.Position.TOP_RIGHT`
- **样式**: `Notify.Style.INFO`（深蓝背景，ℹ 图标）
- **时长**: 4 秒
- **字体**: RichTextLabel + unifont 16px 原生渲染（支持 BBCode）
- **触发次数**: 每次技能施法最多触发一次
- **文本内容**: 用 BBCode 富文本拼接，按 `PhaseData` 字段的存在性动态生成

**完整示例**：

```
┌─────────────────────────┐
│ ℹ 【制势·遏流】            │
│   土×2 → 水×2            │
│   伤害倍率 ×1.00          │
│   附加伤害 10             │
│   施加【壅水】3回合        │
└─────────────────────────┘
```

**字段拼接规则**（实现见 `scenes/levels/base_level/base_level.gd:768`）：

| 行 | 条件 | 格式 |
|----|------|------|
| 首行（必有） | 总是 | `【{category}·{phase_name}】` |
| 第二行（必有） | 总是 | `{攻击元素}×{量} → {目标元素}×{量}`（彩色 BBCode） |
| 伤害倍率行 | 仅当 `damage_multiplier ≠ 1.0` | `伤害倍率 ×{值}` |
| 附加伤害行 | 仅当 `phase_bonus_damage > 0` | `附加伤害 {值}` |
| 施加状态行 | 仅当 `apply_status_id != ""` | `施加【{状态中文名}】{持续}回合` |

### 化势分类名称

| PhaseCategory | 名称 | 说明 |
|---------------|------|------|
| `DOMINANT` (0) | 制势 | 五行相克产生的强力反应（金克木、木克土等） |
| `FOLLOW` (1) | 承势 | 五行相生产生的辅助反应（金生水、水生木等） |
| `ADVERSE` (2) | 逆势 | 不在通知中显示 |
| `SAME` (3) | 同气 | 不触发化势通知 |
| `PLAIN` (4) | 普通 | 不触发化势通知 |

> 💡 提示: 只有 DOMINANT 和 FOLLOW 两种化势会触发三层反馈。其他情况（同气、普通、逆势）只会有伤害弹字，没有 PhaseNotification / PhaseElementPopup / Notify。

### 设计师如何利用

- **验证化势是否触发**：玩一遍关卡时观察屏幕中央是否闪过化势名；如果没闪，说明技能属性和目标当前属性不满足五行相克或相生关系
- **核对伤害数值**：右上角 Notify 里的"伤害倍率"和"附加伤害"可以直接核对 [附录 B § B.6 化势数据一览](appendix-creature-reference.md#b6-化势五行反应数据一览)
- **对比代码日志**：同样的信息会以 `[战斗]` 前缀打印在 Output 面板，可交叉验证（见上方 7.3 节"战斗日志"小节）

## 7.4 常见问题排查

### 问题 1：运行后看不到地图

**可能原因：**
- `TileMaps` 下没有 TileMapLayer
- TileMapLayer 没有设置 TileSet
- TileMapLayer 上没有绘制任何地块

**排查步骤：**
1. 检查场景树中 `TileMaps` 下是否有 TileMapLayer 子节点
2. 选中 TileMapLayer，检查检查器中的 **Tile Set** 是否有值
3. 在 2D 视图中，该层上是否有绘制的地块

---

### 问题 2：角色不显示 / 显示在错误位置

**可能原因：**
- 单位节点不在 `Entities/Units/` 下
- 单位放置位置离地图太远
- `obstacles_tilemap_layer` 未设置

**排查步骤：**
1. 检查单位节点是否在 `Entities/Units/` 路径下
2. 在 2D 视图中，单位是否在地图范围内
3. 检查根节点的 `Obstacles Tilemap Layer` 属性是否已设置

---

### 问题 3：角色无法移动

**可能原因：**
- `MovementManager` 的 `Movement Tilemaps` 未配置
- 地表层没有使用 Terrain 模式绘制
- 所有格子被障碍物覆盖
- 单位的 `move_limit` 已用完

**排查步骤：**
1. 选中 `MovementManager` 节点，检查 **Movement Tilemaps** 是否包含地表层
2. 确认地表层使用了 Terrain 模式绘制（参见 [02-地形绘制](02-terrain-painting.md)）
3. 检查 **Obstacle Tilemaps** 中的障碍物层是否覆盖了你想让角色走的区域
4. 查看战斗日志中 AP 和移动次数的信息

---

### 问题 4：点击角色无反应

**可能原因：**
- 不是当前队伍的回合
- 角色已经行动过了（AP耗尽或手动结束）
- 角色正在移动中
- 过场动画或对话框正在播放

**排查步骤：**
1. 查看顶部标签，确认当前是哪支队伍的回合
2. 确认点击的角色属于当前队伍
3. 确认不在过场动画或对话框中

---

### 问题 5：运行时报错 "Node not found"

**原因：** 关卡脚本中的节点路径与场景树不匹配。

**输出面板中的典型错误信息：**
```
Node not found: "Entities/Units/PlayerB" (relative to "/root/Level1-5")
```

**解决：** 对照场景树中的节点名称，修正脚本中的 `$"..."` 路径。

---

### 问题 6：运行时报错 "obstacles_tilemap_layer is not set"

**原因：** 根节点的 `obstacles_tilemap_layer` 属性未设置。

**解决：**
1. 选中关卡根节点
2. 在检查器中将 **Obstacles Tilemap Layer** 指定为障碍物层
3. 参见 [01-地图创建](01-map-creation.md) 第 2.5 节

---

### 问题 7：移动范围显示不正确（太大或太小）

**可能原因：**
- 地形 Terrain 未正确设置
- 单位的 `move_cost_per_tile` 或 `ap_max` 值异常
- `MovementManager` 的层配置有误
- 单位有移动增/减状态（迟滞、陷裂等）

**排查步骤：**
1. 选中单位节点，展开 UnitData，检查 `ap_max` 和 `move_cost_per_tile` 的值
2. 检查地表层的 Terrain 是否正确（参见 [02-地形绘制](02-terrain-painting.md)）
3. 确认 MovementManager 的 `Movement Tilemaps` 指向正确的地表层
4. 查看战斗日志中是否有状态修正信息

---

### 问题 8：镜头不动 / 镜头位置错误

**可能原因：**
- TileMaps 下没有有效地块
- TileMapLayer 的远处有遗留地块导致边界过大

**排查步骤：**
1. 检查每个 TileMapLayer 是否有误放的孤立地块
2. 尝试缩小镜头（滚轮向下）查看完整地图

---

### 问题 9：技能释放后没有效果

**可能原因：**
- AP 不足无法释放技能
- 释放点没有对方阵营的单位（攻击技能）
- 释放点没有友方单位（辅助技能）
- 技能的 `damage_ratio = 0` 且 `attach_amount = 0`

**排查步骤：**
1. 查看战斗日志中是否有"技能执行失败"的提示
2. 确认目标单位在技能的 `effect_offsets` 范围内
3. 确认阵营关系正确（攻击不能打同阵营，辅助不能加不同阵营）

---

### 问题 10：状态栏不显示技能按钮

**可能原因：**
- 选中的不是活跃单位（不是当前回合的队伍）
- 单位的 UnitData 中没有装配技能（skills 数组为空）
- 单位的 UnitData 未设置

**排查步骤：**
1. 确认选中的单位属于当前正在行动的队伍
2. 检查 UnitData 的 skills 数组是否有内容
3. 如果是运行时装配技能，检查 `_on_level_ready()` 中的代码

## 7.5 调试技巧

### 使用 print() 输出

在关卡脚本中添加 `print()` 语句来观察运行状态：

```gdscript
func _on_level_ready() -> void:
    print("关卡初始化完成")
    print("队伍数量: ", teams.size())
    for i in range(teams.size()):
        print("  队伍 %d: %s, %d 个单位" % [i, teams[i].team_name, teams[i].units.size()])
```

### 使用 Godot 远程场景树

运行游戏后，Godot 编辑器左上角的场景树面板会出现一个 **远程 (Remote)** 选项卡。切换到 Remote 可以查看运行时的实际节点树，确认：

- 单位是否被正确重新挂载到障碍物层
- 各节点的运行时属性值

### 查看战斗数据

在运行时，可以通过远程场景树选中 Unit 节点，查看其 `combat_stats` 属性来确认：

- 当前 HP、AP
- 当前属性和层数
- 已施加的状态列表
- 移动/技能使用计数

### 单独测试地图

如果你只想测试地图绘制（不需要角色和逻辑），可以：

1. 打开地图场景文件（`scenes/levels/maps/` 下的纯地图文件）
2. 按 F6 运行
3. 查看地图显示效果

## 7.6 性能注意事项

对于关卡设计师需要注意的性能相关事项：

- **地图大小**：不建议单层超过 50x50 格。过大的地图会导致 Dijkstra 路径搜索变慢
- **TileMapLayer 层数**：建议不超过 5-6 层。每多一层都会增加渲染开销
- **单位数量**：建议单关卡不超过 15 个单位。过多单位会导致 AI 回合等待时间过长
- **过场图片**：图片分辨率建议与视口分辨率一致（960x540）或窗口分辨率（1920x1080）
